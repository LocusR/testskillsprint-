# BES / SkillSprint

Перенесення дизайну `bes.in.ua` з HTML-прототипів на React + Express.

Джерело дизайну — handoff-бандл Claude Design у [`bes-in-ua-react/project/`](bes-in-ua-react/project).
Прототипи лишаються у репозиторії як референс; продакшн-код живе у `client/` і `server/`.

---

## Структура

```
client/                 Vite + React 19 + TypeScript, CSS Modules
  public/assets/        72 ассети з бандлу (шляхи збережені 1:1)
  src/
    components/
      layout/           Header (бургер-меню), Footer, Layout, Container, Panel
      ui/               Button, Pill, CardGrid, IconCard, VideoCard, Accordion, Modal
      forms/            ApplicationForm + ApplicationModal
      icons/            SVG з прототипів, currentColor
    config/site.ts      маршрути, зовнішні посилання, навігація
    context/            ApplicationModalContext — глобальний стан модалки заявки
    data/               контент сторінок як типізовані модулі
    pages/              SkillSprint / BesLanding / Blog / Article
    styles/tokens.css   дизайн-токени (палітра, радіуси, типографіка, брейкпоїнти)

server/                 Express + TypeScript
  src/
    routes/             /api/health, /api/candidates
    services/           besCenter.ts — форвард заявок у BES Center
    validation/         zod-схема кандидата
    middleware/         404 + error handler
```

## Запуск

```bash
npm install
```

Скопіювати `server/.env.example` у `server/.env` і вписати `BES_CENTER_API_KEY`:

```bash
cp server/.env.example server/.env
```

Підняти обидва сервіси:

```bash
npm run dev
```

- фронтенд — http://localhost:5173
- бекенд — http://localhost:4000 (Vite проксює `/api` на нього)

Інше:

```bash
npm run build       # збірка client + server
npm run typecheck   # tsc --noEmit в обох воркспейсах
npm start           # прод-сервер із server/dist
```

## Docker

```bash
cp .env.example .env      # заповнити ключі
docker compose up -d --build
```

Сайт підніметься на `http://localhost:8080` (порт міняється через `WEB_PORT`).

Дві служби:

| | Що робить |
|---|---|
| `server` | Express у `node:22-alpine`, non-root, healthcheck на `/api/health`. Назовні не публікується — тільки у внутрішню мережу |
| `client` | Статика Vite у `nginx:alpine`: SPA-fallback, gzip, довгий кеш для хешованих ассетів, `no-cache` для `index.html` |

nginx проксює `/api/` на `server:4000`, тож **фронт і API на одному origin** —
у продакшні CORS не потрібен взагалі, а `X-Forwarded-For` доходить до rate-limit
(на сервері вже стоїть `trust proxy`).

> **`VITE_*` вшиваються у бандл на етапі збірки**, а не читаються в рантаймі.
> Тому вони передаються як build-args, і після зміни site key чи GA ID потрібна
> перезбірка: `docker compose build --no-cache client`.
> Секрети бекенду (`BES_CENTER_API_KEY`, `RECAPTCHA_SECRET_KEY`) — навпаки,
> звичайні runtime-env і в образ не потрапляють.

Три файли `.env.example` — це не дублювання: кореневий для `docker compose`,
`client/` і `server/` для локальної розробки без Docker.

## Бекенд

Єдина причина існування Express — **`X-Api-Key` не можна тримати в браузері**.
Форма б'є у власний `/api/candidates`, а вже сервер форвардить заявку в BES Center
зі своїм секретом.

### `POST /api/candidates`

```json
{
  "firstName": "Іван",
  "lastName": "Петренко",
  "middleName": "Олегович",
  "phoneNumber": "380670000002",
  "email": "test@example.com",
  "age": 25,
  "location": "Львів"
}
```

Відповіді:

| Код | Коли |
|-----|------|
| `201` | заявку прийнято і передано в BES Center |
| `400` | не пройшла валідація — у тілі `fieldErrors` для підсвітки полів |
| `429` | перевищено ліміт (10 заявок / 15 хв на IP) |
| `502` / `504` | BES Center недоступний або відповів помилкою |
| `503` | `BES_CENTER_API_KEY` не налаштований на сервері |

Форвардиться на `BES_CENTER_API_URL` з заголовком `X-Api-Key`.
`middleName` — єдине необовʼязкове поле.

### Захист форми

**reCAPTCHA v2 (чекбокс).** Версію визначено емпірично: `api.js?render=<key>`
віддає `400` (так Google відповідає на v2-ключ у v3-параметрі), а v2-віджет ключ
приймає. Токен обовʼязковий у payload і перевіряється через `siteverify`
**до** форварду — боти не доходять до BES Center.

- site key — публічний, лежить у `client/.env` → `VITE_RECAPTCHA_SITE_KEY`;
- secret key — тільки `server/.env` → `RECAPTCHA_SECRET_KEY`.

Якщо секрет порожній: у проді заявки відхиляються (fail-closed), у dev перевірка
пропускається з гучним попередженням у логах, щоб форму можна було тестувати.

> **Ключ прив'язаний до доменів.** На `localhost` віджет покаже «Локального хосту
> немає в списку підтримуваних доменів» — додайте `localhost` у консолі
> reCAPTCHA, щоб тестувати локально.

**Згода на обробку даних** — обовʼязковий чекбокс із посиланням на
[сторінку політики](client/src/pages/Privacy), без нього форма не відправляється.

### Аналітика

GA4 у [analytics.ts](client/src/lib/analytics.ts). Поки `VITE_GA_MEASUREMENT_ID`
порожній — скрипт не вантажиться і жоден запит нікуди не йде; усі функції no-op.
З ключем усе піднімається саме, без правок у коді.

`send_page_view: false` + ручний `page_view` на кожній зміні маршруту — інакше
в SPA GA зарахував би лише перше завантаження. Перегляд відправляється через
`setTimeout(0)`, щоб `usePageMeta` встиг оновити `document.title`.
Успішна заявка шле стандартну подію `generate_lead`.

> Політика згадує cookie та аналітику, але банера згоди немає. Для відвідувачів
> з ЄС його варто додати — скажіть, якщо потрібно.

### `GET /api/health`

Показує `besCenterConfigured: true|false` — чи заданий секрет (сам ключ не віддається).

## Що змінилось порівняно з прототипом

**Адаптивність.** У прототипах не було жодного `@media`: сітки жорстко зафіксовані
(`repeat(3,1fr)`, `repeat(4,1fr)`), а хедер із 5 пунктами меню + соцмережі + CTA
розвалювався на планшеті. Додано брейкпоїнти **1100 / 1024 / 900 / 768 / 640 / 480**:

- хедер згортається в бургер-меню нижче 1100px;
- сітки карток: 4 → 2 → 1, 3 → 2 → 1, 2 → 1;
- hero стає одноколонковим (фото зверху) нижче 900px;
- нижче 640px `vw`-типографіка замінюється фіксованим мобільним масштабом —
  інакше `clamp(13px, 1.05vw, 20px)` на телефоні прилипає до мінімуму й не читається;
- футер вибудовується в колонку нижче 768px.

**Заявки.** У макетах немає жодної форми — усі CTA вели на `t.me/b_eng_s_bot`.
Тепер вони відкривають модалку з полями кандидата, яка ходить у наш бекенд.
Telegram лишився як запасний канал на екрані успіху.

**Доступність.** Додано видимий фокус, `aria-expanded` на акордеоні й бургері,
focus-trap і блокування скролу в модалці, `prefers-reduced-motion`.

**Дрібне.** Рік у копірайті рахується з `Date.now()` замість зашитого «2026».
FAQ переведено з нативного `<details>` на контрольований React-компонент —
React перезаписує атрибут `open` при ре-рендері.

## Анімації та ховери

Параметри зняті з живого `bes.in.ua/skillsprint` і відтворені
на IntersectionObserver + CSS у [animations.css](client/src/styles/animations.css):

| | Як на живому сайті |
|---|---|
| Тривалість | `0.6s` |
| Easing | `cubic-bezier(0.645, 0.045, 0.355, 1)` |
| Сходинка стагера | `0.1s`, стеля ~`0.7s` |
| Заголовки й текст | `slideIn` з `translateY(100%)` + `clip-path`-маска + `fadeIn` |
| Картки й зображення | `fadeIn` (+ легкий `rise`) |
| Меню | підкреслення через `scaleX(0 → 1)` |

Спостерігач вішається на **контейнер** сітки, а картки анімуються по черзі через
`:nth-child` — так не потрібні окремі рефи на кожну картку.
`prefers-reduced-motion` вимикає все.

Ховери: підйом карток `-5px` + тінь, зум зображень `scale(1.05)`,
підкреслення пунктів меню, зсув декоративних ілюстрацій у тарифних картках.

## Розбіжності прототипів і живого сайту

HTML-прототипи з бандлу місцями відстали від продакшну. Звірено з живим сайтом
і виправлено на його користь:

- **`#196c7e` (петроль)** — кольору взагалі не було в прототипах. Ним залиті всі
  три картки «Хто такий BIM спеціаліст» та модулі 1 і 3 у програмі курсу.
- **Помаранчевий градієнт** `#fba162 → #ff7616` на CTA «Хочу навчатися» і
  «Залишити заявку» замість заливки одним кольором.
- **«Хто такий BIM спеціаліст»** — іконка зверху в білій плитці, текст під нею
  (у прототипі було збоку). «Кому підійде курс» лишається як було: іконка збоку,
  кольори teal / orange / dark.
- **«Що на тебе чекає»** — картки в шахівницю темна/світла, іконки в білих плитках.
- **«Програма курсу»** — тиждень помаранчевий (був бірюзовий), останній ряд із двох
  карток відцентрований (сітка 6 колонок по 2 на картку).
- **Метрики** — чотири різні кольори (dark / white / orange / light) і без проміжків.
- **«SkillSprint»** у заголовку та підпис у картці оплати — кольорові акценти.
- **Примітка про кар'єрний шлях** — обіймається декоративними дужками, ключові
  фрази виділені жирним.
- **Історії успіху** — підпис (ім'я + роль) винесений в окрему білу картку під
  відео, а не просто текст під ним.
- **Посади** в історіях і в менторів — помаранчеві `#fba162`, а не бірюзові.
- **«Наша команда»** — карусель на scroll-snap із трьох фото замість одного
  статичного. Саме для неї в бандлі лежали `team-2.png` і `team-3.png`, які
  спершу виглядали як невикористані. Текст отримав жирні акценти.
- **Кнопка хедера** — `clamp(170px, 14vw, 205px)` замість прототипного
  `clamp(150px, 10.7vw, 205px)`: старий варіант дотягувався до еталонних 205px
  лише на ~1900px екрані, тож на звичайному десктопі кнопка виходила ~154px.
- **Цитата** — смуги на фоні тепер ширші за текст. Обидві величини рахуються
  у відсотках одного контейнера, а не двома незалежними `vw`-формулами, які
  на різних ширинах міняли порядок місцями.

## Контент

Тексти, ментори, модулі, FAQ і статті винесені у `client/src/data/`.
Структура `data/blog.ts` навмисно збігається з майбутньою відповіддю `GET /api/posts`,
тож перенесення блогу на бекенд не потребуватиме зміни компонентів.

Секції «Наша команда» і «Що ми пропонуємо» на лендінгу BES вмикаються пропсами
`showTeam` / `showBenefits` — це `<sc-if>` з прототипу.
